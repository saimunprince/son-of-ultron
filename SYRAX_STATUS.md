## Critical Risks

1. **Self-modification has landed twice, and stalls on two-file changes.**
   `d9e60cf` (2026-10-03, docs-only) and `e2f5c27` (2026-10-10, code: an
   nvidia-smi GPU probe in `sysinfo.gpu()` shown by `system_info`, with its
   own new test; gate #3 GREEN, Upstage reviewed Gemini's work, objective 95
   closed on `change_released` with the commit as evidence). The follow-up
   (a Windows CIM fallback so the probe sees this machine's AMD Radeon,
   objectives 97 and 105) failed six attempts: the free brains (Gemini
   flash-lite, Upstage Solar) re-read files in chunks, repeated the same view
   five times, deleted 111 lines with one oversized `str_replace`, and once
   finished the change and its tests (5 passed) but ended without `release`.
   Each failure became a fix (see "Second session"), but no third commit has
   landed yet.
2. **Recovery verifies only editor edits**: the UNCERTAIN recoveries on record
   are `python_execute` operations (a third on 2026-10-10, from the freeze fixed
   in `8f4ce75`); a crash mid-python leaves a human to decide.
3. **`python_execute` write scope is unchecked** (paths live inside code); the
   new permission gate refuses destruction for autonomous work and asks a human
   for unnamed targets, but cannot see where a write lands.
4. **Free-tier brains**: 171 failovers in the journal; Gemini free quota is
   ~20 requests per model per day; quality depends on which brain answers.
   On 2026-10-10 they could not finish a two-file code change in 30 steps,
   echoed SYRAX's own step prompt as a final answer three times, and claimed
   "addressed through code optimization" for `release` objectives with no change.
5. **One frontend unit test file**; the UI is exercised by `tsc`, `eslint`,
   `next build` and the bridge tests, not by component tests.
6. **Another tool's worktrees**: Kilo now keeps
   `~/.local/share/kilo/worktree-pool/son-of-ultron-*/copper-bracket` (at `fc561d6`);
   the earlier `.kilo/worktrees/spice-melon` is gone. Left untouched.
7. **RAM**: the machine ran with < 1 GB free during both sessions; SYRAX skips
   cycles under pressure, by design (885 MB on 2026-10-10). Under that load the
   gate failed twice on tests that pass alone (`test_skillevo`, `test_skills`).

Each item was found live, reproduced in a test, gated GREEN (backend gates),
merged and pushed; SYRAX restarted itself into each.

- `437d802` objectives: human `objective_add` takes machine checks
  (`change_released`, `file_present`, `file_absent`, `quality_case_passes`);
  a release counts only for the objective's own task. Live: it refused to
  close objective 97 on "I am SYRAX. Blood of ULTRON." (no work done), which
  `task_success` would have closed DONE.
- `e2f5c27` **SYRAX's own commit**: the nvidia-smi GPU probe (above).
- `794e75d` autonomy: a failed release attempt hands its rolled-back diff to
  the next attempt's brief; `change_released` objectives get 30 steps.
  Live: objective 105 re-applied the kept diff first.
- `8f4ce75` python_execute: no `multiprocessing.Manager`. At 10:40 its start
  hung inside the event loop and SYRAX froze for 20 minutes (no HTTP, no
  abort). Reproduced: the old code hung > 5 minutes when its child died at
  start; the new code reports the dead worker in seconds. Median call time
  1.80 s → 0.90 s.
- `140c7ab` agent: the same call repeated escalates; the fourth repeat in a
  row ends the task as PARTIAL.
- `05f4cbe` agent: a release objective that changed files is asked once for
  `release` before it may end (objective 105 finished its change and tests,
  then ended without releasing).
- `564988f` editor: keeps each file's line endings. Upstream wrote CRLF on
  Windows; an undone edit left `sysinfo.py` content-identical but "modified".
- `984dc88` python_execute: a pipe closed before the process is reaped is an
  exit, not a timeout (a race the gate hit under load).
- `b799e2f` core: the human's conversation is kept aside during SYRAX's own
  work and restored after. Live: Prince's "hi" at 11:34 reached the brain
  with the autonomous GPU brief as context; SYRAX edited `sysinfo.py` and

Human actions on record: SYRAX was stopped and restarted once (the freeze);

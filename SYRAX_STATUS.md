1. **Self-modification has landed exactly once**: `d9e60cf` (2026-10-03 18:13,
   docs-only: the system-map refresh) went through SYRAX's own `release` —
   gate #2 GREEN on all 8 gates, cross-brain review approved (OpenRouter
   reviewing Gemini's work), `commit.created`, pushed by a human
   (`SYRAX_AUTOPUSH` off). Before it: 0 ok / 4 fail, all four stopped before
   the gate (two "nothing to release", one judge file, one existing test).
   One commit is a proof of mechanism, not a track record; the matrix keeps
   the row YELLOW (failure share 80 %).
2. **Recovery verifies only editor edits**: both UNCERTAIN recoveries on record
   are `python_execute` operations; a crash mid-python leaves a human to decide.
3. **`python_execute` write scope is unchecked** (paths live inside code); the
   new permission gate refuses destruction for autonomous work and asks a human
   for unnamed targets, but cannot see where a write lands.
4. **Free-tier brains**: 171 failovers in the journal; Gemini free quota is
   ~20 requests per model per day; quality depends on which brain answers.
5. **One frontend unit test file**; the UI is exercised by `tsc`, `eslint`,
   `next build` and the bridge tests, not by component tests.
6. **A stray worktree** `.kilo/worktrees/spice-melon` (another tool's); left
   untouched.
7. **RAM**: the machine ran with < 1 GB free during the session; SYRAX skips
   cycles under pressure, by design.

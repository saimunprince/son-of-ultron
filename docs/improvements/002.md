### Missing controls and concrete risks

1. **Words can close an objective.** `task_success` reads only the task's
   status. In the live journal 2 human objectives closed this way (63 and the
   2026-10-03 scenario C objective).
2. **Evidence is not tied to the objective's own work.** `tool_verified`,
   `knowledge_stored`, `skill_verified` read global journal state;
   `change_released` accepted a task-less `commit.created`. A DONE stored only
   the judge's summary, not links to the evidence.
3. **Interrupted work counted.** Nothing kept evidence from an INTERRUPTED
   task out of a completion.
4. **Stale evidence by clock.** "After the objective" was decided by
   timestamp; on Windows `time.time()` ticks every ~15 ms, so an event in the
   same tick as the objective's creation counted (reproduced while building
   this change; the same trap as `a398a54`).
5. **No experiment records.** The live journal held 0 experiments while 10
   release attempts went by (RISE.md, 2026-10-10). A release's outcome lived
   only in loose events.

## 3. Design

The smallest change that keeps every existing test: `autonomy.judge` stays as
it is (its unit tests pin its semantics), and a new layer,
`syrax/contracts.py`, runs after it at all four DONE paths. It may keep or
withdraw a DONE, never create one, and it stores a `contract` beside the
judge's evidence: the ids of the evidence items, their attribution
(`own` / `measurement` / `other-task`), the objective's own tasks, and
whether the contract is machine-verifiable. Releases get their record where
they already run: `DevLoop.release` wraps the existing flow and writes one
experiment per attempt. `contracts.py` joins `devloop.JUDGES`. No change to
the permission policy, the execution guard, the gate, the evaluator's tests
or the human stop path.

## 8. Remaining risks

1. Contradictory evidence is not detected in general (a commit reverted
   later still counts).
2. A crash between `git commit` and the `commit.created` event leaves a
   commit without its event; the contract cannot see it.
3. The experiment record's objective id comes from the single ACTIVE
   objective; a release from a human conversation records none.
4. Skill tests run pytest under the shared Temp folder; on 2026-10-10 another
   project's temporary folder vanished during collection and one bridge test
   failed once (passed 2/2 on rerun). A fixed `--rootdir` for skill tests
   would remove that exposure (`skills.py`, a judge file).
5. Objectives closed before `23e1069` carry no contract; nothing is rewritten.

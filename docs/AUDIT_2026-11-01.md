## 2. How the audit was done

Six read-only audits ran in parallel, one per area:

1. security boundaries;
2. task lifecycle and journal;
3. capability acquisition;
4. self-improvement and release;
5. integrations and platforms;
6. docs against evidence, dependencies and performance.

Each finding gives a file and line, evidence, a severity and a status. Every finding acted on was re-checked here
before it was fixed.

**The security audit was cut short.** The model's safety filter stopped it twice, so only its first finding (F1)
arrived, and `backend/app/` tools and endpoints were not audited. That area is still open.

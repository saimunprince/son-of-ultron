## Follow-up 2026-10-29

- **Own code may not read `backend/config`** (open item 1, reads). For kind `autonomous` it reads the system, the
  interpreter and venv, harmless git config, and the repository entry by entry. It may list the folders down to
  `backend/config` (names only), because Python's import finder lists every `sys.path` folder. File contents stay
  unreadable. `compare_versions`' tests and benchmark run under the write boundary.
- **Skill calls and skill tests are confined** (open item 4). Calls get the python_execute spec: rlimits and process
  group always, Landlock for own work. A skill's tests may change files only in its folder and a private TMPDIR.
- **No credentials for own code** (open item 3). Own work's workers and confined test runs drop secret-looking
  variables, the ssh/gpg agents, the session bus and `CLAUDE_CODE_*`. The live server had inherited
  `CLAUDE_CODE_MESSAGING_TOKEN` from the editor shell that started it; the launcher drops those variables now.
  Residual: `/proc/self/environ` shows a worker's initial block, and Landlock does not mediate `connect()` on
  pathname sockets, so code that hardcodes a socket path is not stopped.
- **E-STOP button in the HUD** (open item 10). It sits beside AUTO; while the stop is on, AUTO cannot be turned on.
- **Network for own code** (open item 2). Own work and its skill calls may open TCP only to
  `SYRAX_OWN_TCP_PORTS` (80, 443, 53) and may bind none (Landlock ABI 4+). The core, UI, browser debug port, local
  model and ssh are unreachable to them. UDP and pathname unix sockets are not covered.
- **Autonomy levels** (open item). The operator sets 1 (observe and research), 2 (experiment), 3 (modify and verify),
  4 (integrate) or 5 (continuous) with the WS message `autonomy_level` or the HUD's L-/L+. The level is a journal row
  that own code cannot write. It is enforced in `permissions.decide` for every own tool call; running code counts as
  level 2. Self-restart needs level 5. Unset means 5 (the behaviour before levels); an unreadable value means 1.
- **Journal integrity chain** (open item). Kept events carry an HMAC chain. Its key lives in `backend/config`,
  where own code cannot reach. `verify_chain` runs at every boot (`integrity.checked`). Limit: backups do not carry
  the key.
- **Experiments** (open item). A success threshold is declared before the run (`min_effect_pct`, never below
  10 %), and overlapping samples are NO_DIFFERENCE. Own work's arms run under the own-work confinement; they are
  not moved to a separate worktree.

## Not fixed (open, ranked)

**Status: NOT FULLY FIXED.** One blocker is left (item 4). The owner settled items 1–3 on 2026-10-29:

1. ~~A human's `python_execute` runs without the kernel boundary.~~ **Closed** in 3f51107 and 87426c9. A human's
   code reads the system and home minus the secret folders, and writes the home's ordinary folders, `/tmp` and the
   workspace. It never writes a home dotfile (except `.cache`) or a repository's `.git`. Network and environment
   stay whole. Proven live: `.ssh` was refused, numpy and the home worked.
2. ~~Still not judges: `agent.py`, `brains.py`.~~ **Closed** in 1ac0b80 by the owner's call: both are judges. A
   self-release or a brief can no longer change them.
3. **The UI trust model: left as is, on purpose.** The core and the UI bind `127.0.0.1` only, so nothing on the LAN
   reaches them. Any local process that could forge an `Origin` runs as the same user and could read `ws.token`
   too, so a token-only rule would add complexity without a boundary.
4. **Ollama on this machine.** The 7B model on CPU reads a 2k prompt in 38 s, and 32k context exhausted RAM. SYRAX's
    ~10.5k prompt needs `OLLAMA_CONTEXT_LENGTH` of 16k or more on the service and is slow: a fallback at best.
    Deferred: the owner's other models share that Ollama and RAM (10/14 GB in use on 10-29).

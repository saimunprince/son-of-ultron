# SYRAX audit and stabilization, Linux (2026-10-28)

The owner moved SYRAX from Windows 11 back to Linux (Ubuntu 26.04, kernel 7.0, Landlock ABI 8) and pasted two
missions: "Full Repository Audit, Autonomous Runtime Stabilization & Verified Self-Improvement" and "Autonomous
Self-Improvement, Continuous Learning & Independent Research Engine". Both say: no push, no deploy, isolated branch,
never weaken a test, report what is not fixed. Work is on branch `stabilize` (worktree `../wt-stab`), rebased onto `d9621a1`.

Code was the evidence. Three read-only audits mapped execution boundaries, the autonomy controller, and research,
learning and honesty; every finding below was checked in code and, where fixed, has a new test that fails on
`e584485` for the stated reason (a "red proof").

## Baseline on Linux (e584485)

- Release gate: **BLOCKED**. pytest did not start: `psutil` is imported by `tools.py`, `guard.py` and two tests,
  but no requirement declares it (Windows had it transitively).
- pytest without those two files: 2411 passed, 16 failed, 18 errors. The 25 docker sandbox failures and errors are
  OpenManus tests outside the gate (`pytest syrax`). 9 SYRAX failures: Windows assumptions (6), psutil (2), and
  `fork` (1, below).

## Follow-up 2026-10-29

- **Own code may not read `backend/config`** (open item 1, reads). For kind `autonomous` it reads the system, the
  interpreter and venv, harmless git config, and the repository entry by entry. It may list the folders down to
  `backend/config` (names only), because Python's import finder lists every `sys.path` folder. File contents stay
  unreadable. `compare_versions`' tests and benchmark run under the write boundary.
- **Skill calls and skill tests are confined** (open item 4). Calls get the python_execute spec: rlimits and process
  group always, Landlock for own work. A skill's tests may change files only in its folder and a private TMPDIR.
- **No credentials for own code** (open item 3). Own work's workers and confined test runs drop secret-looking
  variables, the ssh/gpg agents, the session bus and `CLAUDE_CODE_*`. The live server had inherited
  `CLAUDE_CODE_MESSAGING_TOKEN` from the editor shell that started it; the launcher drops those variables now.
  Residual: `/proc/self/environ` shows a worker's initial block, and Landlock does not mediate `connect()` on
  pathname sockets, so code that hardcodes a socket path is not stopped.
- **E-STOP button in the HUD** (open item 10). It sits beside AUTO; while the stop is on, AUTO cannot be turned on.
- **Network for own code** (open item 2). Own work and its skill calls may open TCP only to
  `SYRAX_OWN_TCP_PORTS` (80, 443, 53) and may bind none (Landlock ABI 4+). The core, UI, browser debug port, local
  model and ssh are unreachable to them. UDP and pathname unix sockets are not covered.

## Not fixed (open, ranked)

**Status: NOT FULLY FIXED.** The blockers are:

1. **A human's `python_execute` runs without the kernel boundary.** It keeps the home and desktop reach the human
   gives it, under the Python guard only (own work is confined since 2026-10-28/29).
2. **Still not judges:** `agent.py` (claim nudges, the permission choke point), `brains.py` (the key store).
   Protecting `agent.py` would remove most of SYRAX's self-improvement scope: owner's call.
3. **The UI trust model.** An allowed `Origin` header is full trust without a token (open since 10-27).
4. **No integrity chain on the journal.** It rests on the file guard and Landlock.
5. **Autonomy levels.** L1 to L5 are not implemented. There is on/off, the emergency stop and budgets. There is no
   token or cost budget: free tiers report no cost.
6. **Experiments** have no predeclared threshold (fixed 10 % noise band) and run in the live tree.
7. **Ollama on this machine.** The 7B model on CPU reads a 2k prompt in 38 s, and 32k context exhausted RAM. SYRAX's
    ~10.5k prompt needs `OLLAMA_CONTEXT_LENGTH` of 16k or more on the service and is slow: a fallback at best.

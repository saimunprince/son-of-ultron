## Findings

### Task runtime
- Statuses PENDING / IN_PROGRESS / BLOCKED / SUCCESS / PARTIAL / FAILED / CANCELLED / INTERRUPTED / UNKNOWN with an
  enforced transition table (`journal.py:45-71`); phases understand → verify derived from events for the UI, never
  stored (`phases.py`). `task.blocked` / `task.unknown` exist but nothing emits them.
- **A request made while SYRAX was busy was dropped**: `server.py` answered "Already executing. Stop it first." and
  `Core.submit` returned None; nothing was saved; the journal's PENDING status (`start_task_sync(pending=True)`) was
  never used. Fixed by Milestone 1 (queue).
- No wall-clock deadline for conversation or autonomous tasks (only quality cases, 240/420 s); no pause; the only
  budget is `max_steps` (20, 30 for releases). MCP tools have no timeout. Error classification is scattered
  (`journal.misuse`, agent refusals, `repro.ENVIRONMENT`, `autonomy.no_brain_answered`); `task.failed` carries no
  error class.
- Recovery classifies interrupted tasks (`journal.py:968-973`), reality-checks editor edits and releases, keeps
  python_execute / skill_create / browser_* UNCERTAIN. `Core.resume` did not refuse UNCERTAIN tasks and the UI offered
  RESUME on every interrupted task; resume does not recreate the worktree, re-route the brain, reset `max_steps` or
  set the phase. No idempotency keys for external side effects. `dismiss` exists in the server but no UI sends it.
- Eight classes of false claims are caught in `agent.py`; not caught: outcome words outside the patterns ("sent",
  "opened"), tests run through python_execute, and a conversation task is SUCCESS whenever the model stops without
  hitting a limit.

### Memory, skills, security
- Memory types fact / preference / rule / observation are `kind='human'` rows told apart by a tag; the prompt takes
  the 60 newest facts whatever the task; retrieval is substring matching; no verified-at or expiry; contradiction
  detection only for conclusions with differing numbers. **`remember` stores model-passed text as a "human said" fact
  at confidence 1.0; `learn` checks only that cited knowledge ids exist.** `forget` is WRITE level with substring
  matching, so autonomous work could delete memories. No export, no in-place correction.
- Skills: tests gate registration (VERIFIED). Version counts verifications, not code changes; no output contract;
  old code overwritten in place (no rollback); `remove` does not stick; no duplicate check. **Not a sandbox**: a
  registered skill runs in a thread of the server process and its test subprocess ran without the python_execute
  guard; a regex scan was the only barrier.
- Permission levels and policy VERIFIED (`permissions.py`). **The editor could overwrite `brains.json` (keys),
  `ws.token` and the journal file, also from autonomous work** (`editor.resolve_path` accepts any absolute path).
  `apply_patch` refuses absolute and `..` paths. Secrets: masking only on final answers; logs and journaled tool
  outputs unredacted; `brains.json` plaintext (0600 is moot on Windows). Auth: `/ws` and `/live` need the token only
  without an Origin; `/token` trusts the Referer; `/self` and `/voice` unchecked. Research/browser text is not marked
  untrusted. **No backups** of `journal.db`, `brains.json`, `memory.json`; no restore procedure.

### Self-improvement, release policy, HUD, docs
- RISE metrics: verified completion exists for objectives only; recovery success has no denominator; **release
  success is inflated** (the daily ledger publish commits through `dl.release` and counts only in the numerator);
  regression rate, repeated-failure rate, human-intervention frequency and cost/latency per verified task are not
  measured.
- Release policy: scope check, judge and existing-test refusal for every kind, autonomous plan + preflight, gate,
  cross-brain review, rollback before commit. **With one enabled brain the review was skipped and the change
  committed unreviewed**; new files were shown to the reviewer by name only; `backend/requirements-syrax.txt` was
  inside SYRAX's change scope although dependencies are the owner's decision; `selfedit.py` (chooses preflight tests)
  and `conftest.py` were not protected. python_execute targets are quoted literals only; isolation runs only under
  the service (`SYRAX_ISOLATE=1`).
- HUD: shows task, tool, phase, step, permission/claim/commit/rollback/recovery lines, voice status. **Five field
  names did not match the backend** (commit hash, failover provider, quality status, skill name, push outcome), so
  those lines printed blanks; `hello.interrupted` ignored; no queue, history, resume/dismiss or rollback controls;
  decorative random numbers in `hud.html`; the HUD tests used made-up payloads.
- Docs: ROADMAP's "strategy fingerprints" TODO is stale (built 2026-10-01); the capability matrix is promised daily
  but regenerated 5 times in 11 days; README says Kokoro TTS (edge-tts), "ten fixed tasks" (61 cases), a wider
  frontend scope than the code allows, memory "in memory.json" (journal-backed); `SYRAX_STATUS.md` header still says
  28 matrix rows (33). `system_map.json` names all 66 modules.

## Backlog (impact · risk · effort)

1. **Task queue** — a human request made while SYRAX works is queued, runs next, is visible and cancellable; the
   autonomy cycle yields. high · medium · medium. *Milestone 1.*
2. **Safety quick wins** — `Core.resume` refuses UNCERTAIN tasks without an explicit, journaled confirmation; the
   editor and every writing tool refuse `brains.json`, `ws.token`, `journal.db*` for every kind and
   `config.toml` / `memory.json` / `mcp.json` for autonomous and eval work; skill tests run under the guard;
   `forget` refused for autonomous work. high · low · low.
3. **Release-policy holes** — a self-change that no second brain can review is held, not committed; new files
   reviewed in full; dependencies out of SYRAX's scope; `selfedit.py` and `conftest.py` protected. high · low · low.
4. **Backups with tested restore** of the journal (sqlite backup API), keys, memory and config, daily from the idle
   cycle, CLI restore only when stopped. high · low · low.
5. **`apply_patch` context tolerance**, decided by replaying the 113 failed diffs against the files at their commit
   (measurement first; a fallback only if a safe strategy recovers a meaningful share). high · medium · medium.
6. HUD truth — the five field names, contract tests against the backend's real payload shapes, queue and interrupted
   rows; the decorative numbers are the owner's call. medium · low · low.
7. RISE metrics the mission names (regression rate, repeated-failure rate, human-intervention count, brain calls and
   wall time per verified objective; unbiased release rate). medium · low · low.
8. Interrupted-task policy at boot, `dismiss` reachable from the UI; memory truth (`remember` from the model's own
   words is an observation, `learn` checks the cited text); per-task deadline and MCP timeout; docs corrections.
9. Owner decisions: keep the PC awake while SYRAX works; `pytest-xdist`; local embeddings; BOOT.
